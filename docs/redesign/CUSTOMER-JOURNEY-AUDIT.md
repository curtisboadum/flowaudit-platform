## External dependencies and explicit gaps

Fresh read-only probes are in [integrations.json](evidence/customer-audit/integrations.json). Production CAL_WEBHOOK_SECRET is empty; CAL_EVENT_TYPE_IDS is absent. Cal settings required sign-in, so actual event ID and webhook configuration require account access. Gemini rejects the key with 403; DeepSeek balance probe reports is_available=false. Revenue Recovery returns 402 DEPLOYMENT_DISABLED. Providers were not enabled or changed.

Real booking submission, signed webhook delivery, durable booking/CRM receipt, cancellation, rescheduling, payment and attendance remain unverified. These require account access and explicit authorization for a booking that can send notifications. Physical iOS/Android devices, actual browser zoom (the in-app keyboard shortcut did not change page dimensions), a fresh end-to-end audio listening review, and every possible provider/network/browser combination were not tested. Mail links were inspected without opening a mail application or sending messages. Automated provider callback simulations must not be treated as verified provider behaviour.
